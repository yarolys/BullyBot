# BullyBot

Асинхронный Telegram-бот на aiogram 3 и PostgreSQL: звуки, приветствия,
кнопки, модерация и распознавание голосовых через отдельный Celery worker.

## Запуск

Python 3.12, PostgreSQL, Redis, ffmpeg. Установить зависимости `poetry install --no-root`.
Скопировать `.envexample` в `.env` (существующий `.env` не перезаписывать).
Указать TOKEN, BOT_ADMIN_ID, параметры PostgreSQL, SQLALCHEMY_URL вида
`postgresql+asyncpg://user:password@localhost:5432/database`.
DATABASE_URL имеет приоритет над SQLALCHEMY_URL.

Перед обновлением сохранить резервную копию базы. Выполнить:

```sh
poetry run alembic upgrade head
poetry run python run.py
```

Для распознавания в отдельном терминале:

```sh
poetry run celery -A src.handlers.audio.celery_cfg:app worker --loglevel=info
```

Или `docker compose up --build -d`: Supervisor запускает миграции, бота и worker.
Существующий каталог `pg_data` сохраняется. В Docker используется REDIS_URL с хостом redis.
Отключение распознавания: `VOICE_RECOGNITION_ENABLED=false`.

## Модерация

Добавить числовые Telegram ID через запятую в MODERATOR_IDS. Владелец BOT_ADMIN_ID
всегда включён. Этот список не даёт доступ к настройкам бота: админкой управляет владелец.
Модераторы из списка могут работать во всех группах, куда добавлен бот.
Выдать боту права администратора с ограничением участников.
Мут работает в супергруппах. Бот должен получать сообщения группы для команд с `!`
и автомодерации: проверить права и настройки Group Privacy в BotFather.

```text
!kick @KandyBobby нафик не нужон тут
!ban 123456 спам
!unban 123456
!mute @username 30m флуд
!unmute @username
```

Ответом на сообщение: `!mute 2h оскорбления`, `!kick причина`.
Сроки: m — минуты, h — часы, d — дни; по умолчанию час, диапазон 1m–366d.
Причина пишется без кавычек и публикуется ботом после успешного действия.
Kick — бан с немедленным снятием бана; участник сможет вернуться по приглашению.
Если снятие бана не удалось, бот сообщает о частичном результате.

Бот запоминает username авторов сообщений и новых участников в каждой группе.
Он не получает всю историю участников. Для неизвестного/неоднозначного username
использовать ID или ответ на сообщение. Перед действием username проверяется через Telegram.
Администраторы Telegram, владелец, разрешённые модераторы и сам бот защищены.
Анонимные команды от имени канала не принимаются.

Автомут выключен по умолчанию. Для включения задать AUTO_MUTE_CHAT_IDS (ID групп через запятую),
AUTO_MUTE_WORDS (отдельные слова через запятую), AUTO_MUTE_SECONDS (600 по умолчанию).
Это точное совпадение слов без учёта регистра, а не анализ смысла: фразы, склонения,
обходы и контекст он не распознаёт. Сообщение не удаляется. Администраторы защищены.

## Звуки

`/user` — добавление звуков участниками, `/admin` — настройки владельца,
`/sounds` — список звуков с пагинацией. Пользователь выбирает имя и отправляет
аудио, голосовое или документ с audio MIME-типом. Файлы остаются у Telegram;
в PostgreSQL хранятся имя, file_id и тип. Повторная отправка не скачивает файл.
file_id относится к конкретному боту и не переносится на другого бота.

Миграция сохраняет существующие записи, присваивая тип audio. Если старый звук
был голосовым/документом и не воспроизводится, удалить запись и загрузить заново.
Старые кнопки списка нужно обновить командой `/sounds`.

Распознавание отдельно скачивает временный файл и отправляет аудио в Google Speech
через SpeechRecognition. Временные файлы удаляются после обработки. Лимит — 2 минуты
и 20 МБ; результат хранится в Redis до часа. Отключить функцию можно через переменную выше.
Синхронная публикация Celery вынесена из event loop через asyncio.to_thread;
конвертация и распознавание выполняются в worker, не в обработчике бота.

## Проверки

```sh
poetry run python -m unittest discover -s tests -v
poetry run python -m compileall -q src run.py
poetry run alembic upgrade head --sql
```

Тесты подменяют Telegram API и очередь. Для проверки перед выкладкой нужна отдельная
тестовая группа и тестовая PostgreSQL: применить миграцию, загрузить каждый тип звука,
проверить права обычного участника и модератора, протестировать мут и кик на тестовом аккаунте.
Существующая рабочая БД автоматически при разработке не изменялась.

## Что ещё требует доработки

- FSM пока в памяти: незавершённые диалоги теряются при перезапуске.
- Настройки приветствий и библиотека звуков общие для всех групп.
- Нужны квоты на добавление звуков и очередь распознавания при большом чате.
- Старые обработчики используют logger.catch и местами скрывают ошибки без ответа пользователю.
- Удаление динамических кнопок использует таймеры; стоит заменить явным завершением режима.
- CI/CD пока старый: нет запуска тестов перед деплоем, отключена проверка SSH host key,
  формирование JSON уведомлений из текста коммита хрупкое. Этот workflow не запускался.
- Python-зависимости обновлены и зафиксированы в poetry.lock; новые обновления нужно проверять тестами.

Правила Telegram API: https://core.telegram.org/bots/api

Для Telegram через HTTP-прокси задайте `TELEGRAM_PROXY_URL=http://user:password@host:port` в `.env`.
Прокси используется ботом и Celery для Telegram API и скачивания файлов; TLS-проверка сохраняется.

## Обновление зависимостей (17 сентября 2026)

Проект использует PEP 621 и Poetry 2. Прямые зависимости перечислены в pyproject.toml,
транзитивные фиксируются в poetry.lock. Удалены неиспользуемые pydub и asgiref.
Redis-клиент выбирается через celery[redis]: Kombu ограничивает его версией <6.5,
поэтому установка Redis-клиента 8.x вручную не поддерживается.

Образы PostgreSQL 15 и Redis 7 получают обновления в пределах текущей основной версии.
Переход PostgreSQL на другую основную версию требует отдельной миграции данных.
Python в Docker остаётся 3.12. Обновление lock-файла: `poetry update`, затем тесты и сборка образа.
